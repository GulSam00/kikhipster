# 아티스트 한국어 이름 검증 스파이크 (2026-10-22)

앱 코드가 아니라 **일회용 검증 스크립트와 그 결과**다. 구현 근거를 남기려고 커밋했다. 다시 돌릴 때는
`PYTHONIOENCODING=utf-8 python _workspace/<script>.py <출력.json>` (iTunes 검색이 분당 20회 제한이라 느리다).

| 파일 | 질문 | 결과 |
|------|------|------|
| `spike_ko_names.py` | 유명 아티스트 30명을 iTunes ID 로 Wikidata(P2850) 조회하면 한국어 라벨이 나오는가 | 30명 중 28명에서 항목을 찾았고 한글 라벨이 기대와 정확히 일치한 것은 24명. **이름 오매칭 0건**(이름이 아니라 ID 로 찾기 때문). 못 찾은 2명은 인디(Epik High·HYUKOH) |
| `spike_ko_coverage.py` | 일반 검색어로 나오는 아티스트 651명(롱테일 포함)의 적중률 | **한글 이름 40.7%**, 영문 표기 그대로 2.0%, 항목은 있는데 ko 라벨 없음 2.6%, **항목 없음 54.7%**. 표본이 인기순이 아니라 검색어 관련도 순이라 무명이 많이 섞인다 |
| `spike_album_fallback.py` | Wikidata 에 없는 한국 아티스트를 KR 앨범 응답으로 보완할 수 있는가 | 가능. 앨범 `artistName` 중 **한글만으로 된 단독 이름**(`&`·`,` 없음)이 `에픽하이`·`혁오` 였다. 서양권 아티스트에는 소용없다(KR 스토어도 영어) |

`spike_peek.py` 는 결과에서 분류별로 무작위 표본을 뽑아 보는 보조 스크립트, `spike_coverage.json` · `spike_album_fallback.txt` 는 위 측정의 원본 출력이다.

**주의**: 괄호 접미(`딘 (가수)`)는 떼야 하고, 한국어 라벨이 영문과 같으면(`NewJeans`, `EXO`) 병기할 한국어 이름이 없는 것으로 본다.
