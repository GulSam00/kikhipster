### T5. 기능 요청 (2026-08-27 접수)

착수 순서는 아래 정렬대로. **결정이 필요한 항목은 "결정:" 으로 표시**했고, 그게 정해지기 전에는 시작하지 않는다.

**작은 것**

- [ ] **탑스터·월드컵 상세에서 내 게시물이면 수정·삭제 버튼을 낸다.**
  지금은 월드컵 상세에 `OwnerEditButton`(수정만) 하나뿐이고 **삭제는 프로필에만 있다.**
  탑스터 상세에는 소유자 버튼이 아예 없다(`useMe()` 는 댓글 판정용으로 이미 쓰고 있어 판정 자체는 붙어 있다).
  프로필의 `OwnerItemActions`(수정+삭제+확인 토스트)를 그대로 재사용하면 된다 —
  단 그건 카드용이라 상세 페이지 배치에 맞게 손봐야 한다. **월드컵 상세는 Server Component** 라
  소유자 판정을 클라이언트 조각으로 빼는 기존 방식(`OwnerEditButton`)을 유지한다
- [ ] **월드컵 만들기·수정의 "담긴 목록"을 카드+썸네일로.**
  지금은 제목만 든 `Badge` 나열이다. 커버는 검색 결과 행(`ResultRow` 의 `Cover`, 36px)에만 있다.
  **월드컵 상세의 후보 그리드(`PoolItemTile`)와 같은 모양으로 맞추는 게 자연스럽다** —
  다만 담긴 목록에는 "빼기" 동작이 붙어야 해서 타일에 삭제 어포던스를 얹어야 한다

**중간**

- [ ] **탑스터에서 공개/비공개 옵션 제거.** **확정(2026-08-27): 컬럼까지 지운다** — alembic 마이그레이션 동반.
  지금 DB에 **비공개 탑스터가 1건 있다**(전체 5건 중) — 마이그레이션 시점에 공개로 바뀐다.
  영향 범위는 백엔드 7곳(목록 필터, 상세 접근 제어, **댓글 접근 제어**, 생성, 수정, 유저별 목록)과
  스키마 3곳, 프론트 에디터 옵션 1개. **접근 제어 분기가 사라지는 것이라 응답 코드가 바뀐다** —
  비공개 탑스터에 대한 403/404 경로가 없어지므로 그 동작에 기대던 곳이 없는지 확인할 것
- [ ] **탑스터·월드컵 공유에 메타데이터(OG) 추가 — 썸네일 포함.**
  현재 `generateMetadata`·`openGraph` **0건**이다(완전 신규).
  월드컵 상세는 Server Component라 바로 붙지만, **탑스터 상세는 Client Component(`'use client'`)라
  `generateMetadata` 를 쓸 수 없다** — 서버/클라이언트 분리가 선행된다.
  썸네일은 **확정(2026-08-27): `next/og` 의 `ImageResponse` 로 서버에서 새로 그린다.**
  기존 `lib/topster-image.ts`(252줄)는 재활용할 수 없다 — `'use client'` 에 `CanvasRenderingContext2D`·
  `Image`·`toBlob` 등 **브라우저 전용 API** 위에 세워져 있는데, OG 썸네일은 크롤러가 URL을 긁을 때
  **서버에서** 만들어져야 한다. `ImageResponse` 는 satori 기반이라 canvas를 못 쓰고, 서버로 옮기려면
  `node-canvas` 같은 네이티브 의존성이 붙어 Fargate 이미지 빌드에 부담이 된다.
  커버가 mzstatic 외부 URL인 건 `ImageResponse` 에서도 불러올 수 있어 문제가 안 된다

**큰 것 — 플레이 흐름 재설계 (4·5는 한 덩어리)**

- [ ] **"시작하기"를 누르면 play 라우트로 이동하고, 강수는 거기서 고른다.**
  지금은 상세 페이지의 `PlayStarter` 에서 강수를 고른 뒤 `POST /plays` → `/play/{id}` 로 간다.
  **`playId` 는 강수를 정해야 생기므로**(POST 본문에 `size`) 강 선택 화면은 playId 없이 열 수 있는
  주소가 필요하다. **확정(2026-08-27): `/tournament/{id}/play`** — 주소에 어느 월드컵인지가 들어 있어
  새로고침에 견디고, 뒤로가기가 월드컵 상세로 자연스럽게 떨어지며, `/play/[playId]` 와 라우팅이
  겹치지 않는다(`/play/new` 였다면 `playId="new"` 로 잡힐 자리를 두고 다퉜다).
  강수를 고르면 `POST /plays` 후 `/play/{playId}` 로 이동한다
- [ ] **플레이 화면 개편 — 카드 확대 + 배경 대진표 + 승자가 올라가는 애니메이션 + 우측 상단 전환 버튼.**
  **데이터는 이미 다 있다.** `PlayResponse.rounds` 가 전체 라운드(`round_num`·`match_num`·`item_a_id`·
  `item_b_id`·`winner_id`)를 통째로 준다 — DESIGN.md 가 우려하던 "트리를 그릴 데이터가 없다"는
  월드컵 재설계로 이미 해소됐다.
  **DESIGN.md § Visual reference 의 방침과 어긋난다:** 거기엔 "'대진표 보기' 버튼 → `Dialog`(풀스크린)
  안 pan/zoom" 으로 적혀 있는데, 요청은 "**배경**에 상시 표시 + 우측 상단 **전환** 버튼"이다.
  **먼저 DESIGN.md 를 고치고 시작한다**(정본이 코드보다 낡는 걸 이번 세션에 이미 두 번 겪었다).
  § Mobile 도 같이 봐야 한다 — 배경 대진표는 가로가 넓어져 "페이지 가로 스크롤 금지" 와 부딪힌다
